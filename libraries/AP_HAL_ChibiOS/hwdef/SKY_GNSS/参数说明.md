# SKY_GNSS DroneCAN 外设参数说明

本文档说明 **SKY_GNSS**（基于 STM32F412Rx 的 AP_Periph DroneCAN 外设）固件实际暴露的参数，
重点覆盖 **CAN 通信**、**GNSS/GPS**、**罗盘(Compass)**、**气压计(Baro)** 四类。
所有参数名、范围与取值均取自当前固件源码与本板 `hwdef.dat` 编译结果，确保与你在 Mission Planner
里看到的节点参数一致。

> 说明：参数表中的“默认值”为本板编译后的实际默认值；“重启”一列表示修改后是否需要重启节点才生效。

---

## 一、总体概念（先看这里）

DroneCAN 系统的参数分布在 **两侧**，不要混淆：

- **节点侧（本板 SKY_GNSS）**：即本文档所列参数，决定本节点如何上 CAN 总线、如何驱动它本地连接的
  M9n GPS / IIS2MDC 罗盘 / BMP581 气压计，并把数据通过 DroneCAN 发布出去。
- **飞控侧（Autopilot）**：决定飞控是否开启 DroneCAN、是否接收并使用这些传感器（见第七节）。

本板硬件能力（影响“哪些参数存在”）：

- **CAN 接口数 = 1**（F412 只有 1 路 bxCAN）→ 因此 **没有** `CAN_PROTOCOL` / `CAN2_*` / `CAN3_*`。
- **不支持 CAN FD** → **没有** `CAN_FDMODE` / `CAN_FDBAUDRATE`。
- **未启用 SLCAN** → **没有** `CAN_SLCAN_CPORT`。
- **未定义 CAN1 终端电阻 GPIO**（本板用的是 `CAN1_SILENT`/PB5）→ **没有** `CAN_TERMINATE`。
- **GPS/罗盘/气压计实例数均为 1**。
- 这是外设固件（`HAL_BUILD_AP_PERIPH`），罗盘/气压计的“标定/方向/高度解算”类参数被裁剪掉，
  这些工作由飞控侧完成（见第四、五节说明）。

## 二、CAN 通信参数（核心）

本板实际只有两个 CAN 参数：

| 参数 | 含义 | 范围 | 默认值 | 重启 |
|---|---|---|---|---|
| `CAN_NODE` | 本节点在 CAN 网络上的 DroneCAN 节点 ID | `0` ~ `127` | `0` | 是 |
| `CAN_BAUDRATE` | CAN1 接口波特率（bit/s） | `10000` ~ `1000000` | `1000000` | 是 |

### `CAN_NODE`
- **作用**：节点在总线上的唯一身份。`0` 表示向 DNA（动态节点分配）服务器申请一个 ID；
  非 0（1~127）则强制使用该固定 ID 并忽略 DNA。
- **调参建议**：
  - 单 GPS 节点、想省心 → 保持 `0`，由飞控做动态分配。
  - 总线上有多个同类节点、或需要在日志/参数树里稳定区分 → 设固定 ID（如 `1`、`125`），
    并确保 **同一总线上不重复**。
  - 修改后需 **重启** 节点。

### `CAN_BAUDRATE`
- **作用**：CAN1 物理波特率，必须与飞控该 CAN 口波特率一致。
- **调参建议**：
  - 默认 `1000000`（1 Mbps）为 DroneCAN 标准速率，**优先保持**。
  - 仅当总线很长 / 走线质量差 / 与只支持低速的旧设备共线时，才降到 `500000` 等，
    并同步修改飞控侧（`CAN_P1_BITRATE`）。
  - 两侧速率不一致 → 节点无法上线。修改后需 **重启**。

> 上述两参数即“GNSS 的 CAN 参数”。`CAN_PROTOCOL`、`CAN2_*` 等在本板不存在，无需设置。

## 三、GNSS / GPS 参数

GPS 参数分“全局”（`GPS_*`）与“实例”（`GPS1_*`）两组。本板连接 **M9n（USART2）**，
节点直接驱动并配置该模块，再把定位结果通过 DroneCAN 发布。

### 3.1 全局参数

| 参数 | 含义 | 取值 / 范围 | 默认值 | 重启 |
|---|---|---|---|---|
| `GPS_PORT` | GPS 所在串口号（本板 = SERIAL3 = USART2） | `0`~`10` | `3` | 是 |
| `GPS_NAVFILTER` | 导航动力学模型（影响滤波假设） | 0:Portable,2:Stationary,3:Pedestrian,4:Automotive,5:Sea,6:Airborne1G,7:Airborne2G,8:Airborne4G | `7`(Airborne2G, 本板 defaults.parm; ArduPilot 原默认 8) | 否 |
| `GPS_SBAS_MODE` | SBAS 星基增强 | 0:关闭,1:开启,2:不改动 | `2` | 否 |
| `GPS_MIN_ELEV` | 参与解算的卫星最小仰角(°)，`-100`=用模块默认 | `-100` ~ `90` | `-100` | 否 |
| `GPS_INJECT_TO` | RTCM/注入数据的目标 GPS | 0:第1个,1:第2个,127:全部 | `127` | 否 |
| `GPS_RAW_DATA` | 原始观测量记录（ublox RXM） | 0:忽略,1:始终,5:每5样本一次 | `0` | 是 |
| `GPS_SAVE_CFG` | 是否把配置写入 GPS 模块掉电存储 | 0:不保存,1:保存,2:按需保存 | `2` | 否 |
| `GPS_AUTO_CONFIG` | 是否由固件自动配置 GPS | 0:不自动,1:仅串口GPS,2:含DroneCAN | `1` | 否 |
| `GPS_DRV_OPTIONS` | 后端附加选项（位掩码） | bit2:强制波特率115200 等 | `0` | 否 |

**调参建议（全局）**
- `GPS_AUTO_CONFIG` 保持 `1`：本板需要固件去配置 M9n 的刷新率/星座/SBAS，
  关掉后 `GPS1_GNSS_MODE`、`GPS_SBAS_MODE` 等将不再下发到模块。
- `GPS_NAVFILTER` 本板默认 `7`(Airborne2G，与 PX4 对所有机型的默认一致)；`8`(Airborne4G) 是垂直速度
  过程噪声最大的模型。地面测试/静止基准可临时用 `2`(Stationary)。见 3.3 节。
- `GPS_SBAS_MODE`：国内一般保持 `2`（沿用模块默认）；若所在区域 SBAS 可靠可设 `1`。

### 3.2 实例参数（`GPS1_`）

| 参数 | 含义 | 取值 / 范围 | 默认值 | 重启 |
|---|---|---|---|---|
| `GPS1_TYPE` | GPS 类型/协议 | 0:None,1:AUTO,2:uBlox,5:NMEA,9:DroneCAN,20:AllyStar,24:UnicoreNMEA … | `1`(AUTO) | 是 |
| `GPS1_GNSS_MODE` | 启用的卫星系统（位掩码，0=用模块默认） | bit0:GPS,1:SBAS,2:Galileo,3:Beidou,4:IMES,5:QZSS,6:GLONASS | `0` | 否 |
| `GPS1_RATE_MS` | 定位输出周期(ms) | 100:10Hz,125:8Hz,200:5Hz（范围50~200） | `200`(5Hz) | 否 |
| `GPS1_POS_X/Y/Z` | 天线相对机体原点的安装偏移(m) | `-5` ~ `5` | `0` | 否 |
| `GPS1_DELAY_MS` | 量测延迟补偿(ms)，0=用该 GPS 默认 | `0` ~ `250` | `0` | 是 |

**调参建议（实例）**
- `GPS1_TYPE`：保持 `1`(AUTO) 即可自动识别 M9n(ublox)；若想跳过自检、加快启动，可固定为 `2`(uBlox)。
  注意：这里是“本节点连接的物理 GPS 类型”，**不是** `9`(DroneCAN)；`9` 是飞控端用来接收本节点的设置。
- `GPS1_RATE_MS`：**M9n 强烈建议保持 `200`(5Hz)**。本板已用 `GPS_MAX_RATE_MS=200` 把最慢限制为 5Hz；
  提高到 10/20Hz 对 M9n 往往 **降低定位质量**，得不偿失。
- `GPS1_GNSS_MODE`：默认 `0`（沿用模块出厂星座）。如需自定义，多星座组合示例
  `GPS+Beidou+Galileo+GLONASS` = bit0+2+3+6 = `1+4+8+64` = **`77`**。
  注意启用过多星座可能超出 5Hz 带宽，按需取舍。
- `GPS1_POS_*`：天线安装偏移一般 **在飞控侧** 按整机布局设置即可；节点侧保持 `0`。

### 3.3 多普勒垂速偏差（T900 实测）与节点固件的关系

**现象**（T900 机载节点 0x857B03，M9n，5 架次悬停日志，飞控侧 `sensor_gps.vel_d_m_s`）：
起飞→降落对原始多普勒垂速积分做闭合（同点起降，真值 0 m），5 架次全部为负：
`-0.16 / -0.50 / -0.60 / -0.65 / -1.05 cm/s`（08_47_21 / 12_34_55 / 06_14_32 / 07_15_01 / 10_40_17），
即接收机报告的垂速比真实值**恒偏低约 0.6 cm/s**（纯偏置，±25 m 匀速升降段无比例误差；水平多普勒无此偏差）。
悬停噪声 5.5 cm/s（5 Hz，AR(1) ρ≈0.6）。若飞控纯积分多普勒垂速做高度保持，会以约 0.4 m/min 缓慢爬升。

**节点固件做了什么**（`AP_GPS_UBLOX.cpp`）：M9n 走传统 `CFG-NAV5` 路径，固件**只改写** `dynModel`
（=`GPS_NAVFILTER`）和 `minElev`（`GPS_MIN_ELEV`≠-100 时），其余 NAV5 字段（fixMode、static hold、
cnoThresh 等）保留模块出厂/掉电存储值；速度不做任何处理，`NAV-PVT.velD`(mm/s) 直接进
DroneCAN `Fix2.ned_velocity`（float16，对 cm/s 量级无舍入偏差）。因此这个偏差**不是节点固件算出来的**，
而是接收机导航滤波器自身的（钟漂与垂速强相关：所有卫星都在地平线以上，共模测速误差会部分被归到垂速；
垂向过程噪声越大的模型越容易吸收这部分误差）。

**能在节点侧做的**：
1. `GPS_NAVFILTER 8→7`（已改为本板默认；`6` 更平滑，建议地面 A/B 后再定）。
2. 地面 A/B（无需重刷，飞控 nsh 下 `uavcan param set <node> GPS_NAVFILTER 6/7/8`，`uavcan param save <node>`）：
   飞机静置（先电机不转 5 min，再怠速/解锁 5 min），飞控侧 `SDLOG_MODE=1` 从上电记录，
   对比各模型下 `vel_d_m_s` 的均值（真值 0）与标准差、以及升温期与稳温期是否不同。
3. `GPS1_RATE_MS 200→100`（10 Hz）只减少飞控侧观测器看到的噪声，不改偏差，M9n 需验证不掉星。
4. 不建议提高 `GPS_MIN_ELEV`：低仰角星是钟漂的参考，去掉会**加重**垂速/钟漂耦合。

偏差本身在飞控侧由 F8 垂直观测器的气压位置锚（`A3_INS_ALT_TYPE=2` + `A3_INS_BARO_TAU`）兜底；
飞控另有地面基线学习器（静置时对原始多普勒垂速求均值/标准差，`DEBUG_FLOAT_ARRAY 0x474E`），
DronePilot“GPS 定位精度”页显示并可一键写入 `A3_INS_VZ_BIAS`（进观测器前 `v − BIAS`）。上述 A/B 也可直接在该页读数（偏置 ±2σ、噪声 std、ρ₁）。

## 四、罗盘（Compass）参数

本板罗盘为 **IIS2MDC（I2C1, 0x1E）**。作为 DroneCAN 外设，节点只负责 **采集并发布原始磁数据**；
**真正的标定（偏置/软铁/方向）在飞控侧完成并存储**。因此节点侧罗盘参数很少：

| 参数 | 含义 | 取值 / 范围 | 默认值 | 重启 |
|---|---|---|---|---|
| `COMPASS_ENABLE` | 启用罗盘（含数据发布） | 0:关闭,1:开启 | `1` | 是 |
| `COMPASS_FLTR_RNG` | 采样接受范围（偏离均值的百分比，0=关闭） | `0` ~ `100` % | `0` | 否 |
| `COMPASS_DISBLMSK` | 禁用指定驱动类型（位掩码） | …22:IIS2MDC 等 | `0` | 否 |
| `COMPASS_DEV_ID` | 罗盘设备 ID（自动探测，只读） | 自动 | 自动 | — |
| `COMPASS_DIA` / `COMPASS_ODI` | 软铁标定对角/非对角项（由标定流程写入） | 标定值 | 1/0 | — |

**调参建议**
- 正常使用保持 `COMPASS_ENABLE=1`、`COMPASS_FLTR_RNG=0`。
- I2C 走线较长、磁数据有噪声跳变时，可把 `COMPASS_FLTR_RNG` 设为 `5`~`20` 抑制离群点。
- **偏置/方向（OFS、ORIENT、USE 等）在本节点不存在**，请在飞控里对该 DroneCAN 罗盘做正常的
  “罗盘校准”。安装方向也在飞控侧设置（`COMPASS_ORIENT` 等）。
- `COMPASS_DISBLMSK` 一般保持 `0`；仅在需要屏蔽某类驱动自动探测时使用。

## 五、气压计（Baro）参数

本板气压计为 **BMP581（I2C3, 0x46）**，在 `hwdef` 中已硬编码绑定，节点负责发布原始气压/温度，
**高度解算与地面气压标定在飞控侧完成**。

| 参数 | 含义 | 取值 / 范围 | 默认值 | 重启 |
|---|---|---|---|---|
| `BARO_ENABLE` | 启用气压计 | 0:关闭,1:开启 | `1` | 否 |
| `BARO_FLTR_RNG` | 采样接受范围（偏离均值百分比，0=关闭） | `0` ~ `100` % | `0` | 否 |
| `BARO_EXT_BUS` | 探测外部 I2C 气压计的总线号（-1=按 PROBE_EXT 探测全部） | `-1`,`0`,`1`,`6` | `-1` | 否 |
| `BARO_PROBE_EXT` | 要探测的外部气压计类型（位掩码） | …13:BMP581 等 | `0` | 否 |
| `BARO_1_DEVID` | 气压计设备 ID（自动探测，只读） | 自动 | 自动 | — |

**调参建议**
- 保持 `BARO_ENABLE=1`。本板 BMP581 已在 `hwdef` 静态绑定，**无需** 依赖 `BARO_EXT_BUS`/`BARO_PROBE_EXT`
  去探测，二者保持默认即可。
- 长 I2C 线或气压数据抖动时，可把 `BARO_FLTR_RNG` 设为 `1`~`5`。
- 地面气压、海拔偏移、主气压计选择等参数 **在节点侧不存在**，由飞控统一处理。

## 六、其他外设参数（蜂鸣器 / LED）

| 参数 | 含义 | 取值 / 范围 | 默认值 |
|---|---|---|---|
| `BUZZER_VOLUME` | 蜂鸣器音量（MLT-7525, PB10） | `0` ~ `100` % | `100` |
| `LED_BRIGHTNESS` | RGB LED 亮度（8×WS2812, PB0） | `0` ~ `100` % | `100` |

- 蜂鸣器平时由飞控经 DroneCAN `BeepCommand` 控制；本板另有 **上电自检鸣叫**（固件内 2700Hz，约 200ms）。
- LED 启动“彩虹”动画亮度在固件中固定，`LED_BRIGHTNESS` 主要作用于 DroneCAN 灯光指令。

> 另有少量系统参数：`BRD_SERIAL_NUM`（序列号，显示在 CAN App Name）、`DEBUG`（调试位掩码）、
> `FORMAT_VERSION`（参数格式版本，勿手改）。

## 七、典型配置与上车调参流程

**1) 节点侧（SKY_GNSS，通常保持默认即可）**
- `CAN_NODE=0`、`CAN_BAUDRATE=1000000`
- `GPS1_TYPE=1`(AUTO)、`GPS1_RATE_MS=200`(5Hz)、`GPS_AUTO_CONFIG=1`、`GPS_NAVFILTER=7`(Airborne2G)
- `COMPASS_ENABLE=1`、`BARO_ENABLE=1`

**2) 飞控侧（启用 DroneCAN 并接收本节点）**
- `CAN_P1_DRIVER=1`（第 1 个 CAN 驱动）
- `CAN_D1_PROTOCOL=1`（DroneCAN）
- `CAN_P1_BITRATE=1000000`（与节点 `CAN_BAUDRATE` 一致）
- `GPS_TYPE=9`（DroneCAN）→ 接收本节点 GPS
- 罗盘：在飞控里对自动出现的 DroneCAN 罗盘执行 **罗盘校准**，并按安装方向设置 `COMPASS_ORIENT`
- 气压计：DroneCAN 气压计会自动出现并参与高度解算

**3) 排查要点**
- 节点不上线：先查两侧 **波特率是否一致**、`CAN_NODE` 是否冲突、终端电阻是否到位。
- 无定位：查 `GPS1_TYPE`/`GPS_AUTO_CONFIG`、M9n 接线（USART2: TX2=PA2, RX2=PA3）。
- 改完 `CAN_*`、`GPS1_TYPE`、`GPS1_DELAY_MS` 等“重启=是”的参数后，务必 **重启节点**。
